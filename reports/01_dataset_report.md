## Assumptions and unknowns

- The self-evaluation notebook's `get_pq_score` is reproduced exactly (strict `IoU > 0.5`, per-annotator-image grouping, global sum aggregation, 0.0 when the denominator is 0). SQ and RQ are **our own addition** (standard PQ = SQ * RQ decomposition); the notebook itself does not return them.
- Disk centre/radius are fit with Otsu threshold + largest connected component + `radius = sqrt(area/pi)`, not a proper circle (Hough/least-squares) fit — adequate for a first pass but will be biased on cloudy/partial frames (see worst-5 by noise above).
- 'Minimum width' is approximated as `2 * min(distance_transform(mask) at skeleton pixels)`, not a true medial-axis minimum width; it can be noisy for very short/stubby instances with few skeleton pixels.
- 'Touching/overlapping' same-annotator instances uses a 1px dilation test, a looser rule than pixel-exact adjacency; chosen because filament boundaries are hand-drawn polygons and can leave a 1px gap between what is visually one touching pair.
- **The 64x64-correlation near-duplicate check conflicts with this data, per CLAUDE.md's rule to flag rather than guess**: measured on *arbitrary* (almost certainly unrelated) train-train pairs, raw-pixel correlation has mean=0.968, median=0.980, p95=0.993, p99=0.997 — because every full-disk H-alpha frame shares the same bright-disk/limb-darkening shape, 'any two frames of the Sun' are already correlated ~0.97-0.98 at this resolution, barely below the 0.99 threshold. The counts above (train-train and train-train/test near-dup pairs) should **not** be read as genuine near-duplicate frames; a high-pass/structure-only variant was tried and the background rate dropped only to ~0.92 median, still not selective. A real near-duplicate check for this dataset likely needs timestamp proximity as a prior (two frames minutes apart are candidates; two frames years apart are not, regardless of correlation) or a learned/perceptual similarity measure — flagged as an open question below rather than substituted unilaterally.
- Elongation and off-disk fractions are not verified against any ground truth from the organisers (no such reference exists); they are descriptive only.
- The round-trip submission (GT rasterised as a 'prediction') found **["2 image(s) have overlapping masks, e.g. ['20120523163014Mh', '20210815140550Bh']"]** via `validate_submission.py` — i.e. a couple of single-annotator images have genuinely overlapping GT instance polygons (not a bug in rasterisation/RLE: the pixel-exact and PQ=1 checks below still pass). Worth knowing because a real model submission that overlaps masks will fail this same validator check.

## Leakage risks

- 33 test frames share a calendar day with a train frame, and 3 fall within ±1h of a train timestamp. **Not used for CV or model selection** — reported only as a risk if any future step were to peek at test-adjacent frames.
- 0 exact-hash train/test duplicate pairs — the real signal here, and a clean one. The 16619 'near-duplicate' train/test pairs are **not trustworthy** given the background-correlation caveat above and should not be acted on without a better similarity measure.
- Repeated annotator entries for the same physical file (the 1154-vs-707 gap) are a leakage risk for any split that groups by `image_id` instead of by physical file — `splits.py` groups by `file_stem` and `date`, never by `image_id`, by design.

## Implications for modelling

- **Input resolution**: images are [[2048, 2048]], uint8 single-channel. Full resolution for inference/scoring; training likely needs tiling or downsampling given the 8 GB Mac dev budget (Kaggle GPUs for full-res training).
- **Instance separability**: 0.5% of instances touch/overlap a same-annotator neighbour, so naive connected-components-as-instances will under-count merged filaments — some instance-aware or boundary-aware step is needed.
- **Label strategy for multiple annotators**: see the inter-annotator section above; human-ceiling PQ is 0.3399, boundary IoU is comparatively high (count=4.29e+03, mean=0.634, std=0.0774, min=0.5, 25%=0.572, 50%=0.629, 75%=0.693, max=0.862) while a non-trivial fraction of disagreement is instance identity (one-to-many: 253, many-to-one: 253, unmatched: 2840) — this argues for **keeping boundary quality and instance identity as separate concerns**: union-of-annotators risks merging instances that one annotator split and another didn't; training on one annotator's instance *boundaries* per sample while treating instance splits/merges as the harder, separate problem is the more defensible default than a naive union or an arbitrary single-annotator choice. A soft-consensus pixel map (useful for a semantic U-Net stage) and separate per-annotator instance samples (useful for an instance or boundary-aware stage) are both supported by this split; **plain majority-vote union of instances is not recommended** given the one-to-many/many-to-one rates above.
- **Preprocessing needs**: limb darkening is visible in the radial profile (see `reports/figures/01_radial_profile.png`); a per-image or per-site radial normalisation is worth testing before any CNN input stage. Noisy/clouded outliers (worst-5 above) may need to be downweighted or excluded from early baselines.

## Prioritised hypotheses for Spec 02

1. A semantic U-Net + connected-components post-processing baseline will under-perform mainly on merged/touching filaments (0.5% of instances touch a same-annotator neighbour) rather than on boundary quality — validate by comparing pixel-level IoU vs instance-level PQ on the baseline.
2. Radial (limb-darkening) normalisation improves segmentation of near-limb filaments more than disk-centre filaments — validate by stratifying val PQ by `centroid_r_over_R`.
3. Per-annotator instance samples (not a union) give a cleaner training signal than consensus union, because union inflates many-to-one/one-to-many ambiguity at train time — validate by comparing val PQ of a model trained on per-annotator samples vs union labels, on the same images.
4. The handful of flagged noisy/partial frames (worst-5 by noise) should be held out of the first baseline's training set and reported separately, since they may dominate error analysis disproportionately to their count.
